# VORTEX HUB: WEBSITE AND CLIENT DASHBOARD BUILD BRIEF

## 1. Project overview

Create a modern, premium and user-friendly website called **Vortex Hub**.

Vortex Hub is a digital services and consultancy platform connecting clients directly with professional support for:

* Digital products and graphic design.
* Professional document formatting and presentation.
* Business and personal websites.
* AI automation solutions.
* One-to-one digital and AI consultancy.

The business works with both **individual clients** and **business clients**.

At this stage, Vortex Hub is not a multi-vendor marketplace. It is a professional client platform where customers can discover services, submit a project request, book a consultation and later access a secure dashboard to manage their work with Vortex Hub.

## 2. Main objective

Build a website that feels:

* Human.
* Professional.
* Clear.
* Trustworthy.
* Creative.
* Technology-aware, without looking artificial or generic.

The website must make potential clients feel that they are dealing with a real person and a professional creative digital business, not an automated template company.

## 3. Important design instruction: avoid generic AI website styling

Do not create a stereotypical AI-generated landing page.

Avoid:

* Overused purple neon gradients across every section.
* Floating glowing orbs everywhere.
* Generic robot illustrations.
* Fake futuristic dashboards filled with meaningless charts.
* Empty buzzwords such as “revolutionise your future” without practical explanation.
* Excessive glassmorphism.
* Too many animations.
* Overly corporate stock imagery.
* Fake client logos or fake testimonials.
* A cold, automated tone of voice.

The design must feel intentionally crafted by a human designer.

Use a visual style inspired by a small premium digital studio: calm, confident, minimal and welcoming, with subtle technology details.

Technology should be communicated through the quality of the experience, not through clichés.

## 8. Visual direction

### Overall design concept

Create a clean, editorial-style digital studio website with subtle technical elements.

The layout should combine:

* Spacious sections.
* Strong typography.
* Carefully designed service cards.
* Realistic interface previews.
* Minimal decorative graphics.
* Clear conversion buttons.
* Small human touches, such as welcoming copy and simple explanations.

### Colour palette

Use a refined palette similar to the following:

* Primary background: deep ink navy, `#0D1117`.
* Light background sections: warm off-white, `#F7F5F0`.
* Primary text on dark background: soft white, `#F5F5F2`.
* Primary text on light background: charcoal, `#15181D`.
* Main accent: refined indigo, `#5147E5`.
* Secondary accent: muted blue-teal, `#3B9EAE`.
* Border colour: subtle warm grey, `#DDD8D0`.

Do not overuse gradients. A gentle indigo-to-teal gradient may appear only in small highlighted areas, buttons, icons or a single hero visual detail.

### Typography

Use modern and readable typography.

Suggested approach:

* Main headings: a distinctive but elegant font, such as Instrument Serif or a similar editorial font, used carefully.
* Body text and interface: Inter, Manrope or a similar highly readable sans-serif font.

Headings should feel personal and confident. Interface labels should remain simple and highly readable.

### Buttons

Primary button:

* Filled indigo background.
* White text.
* Rounded but not excessively pill-shaped.
* Label: “Start a project”.

Secondary button:

* Transparent or light background.
* Defined border.
* Label: “Book a consultation”.

### Cards

Service cards should be simple and elegant:

* Clear title.
* One short paragraph.
* Small, meaningful icon.
* One link such as “Explore service”.
* Gentle hover state.

Do not use decorative cards that add no meaning.

### Imagery and graphics

Use realistic visuals such as:

* A clean project brief screen.
* A document design preview.
* A website wireframe preview.
* A simple automation workflow diagram.
* An authentic workspace or creative process image if appropriate.

Do not use robots, holograms, fake data visualisations or generic AI graphics.

## 21. Security requirements for later implementation

When backend functionality is added, follow these rules:

* Never expose secret keys in frontend code.
* Use secure authentication.
* Keep client files private.
* Clients must only access their own projects, messages and files.
* Admin access must be protected separately.
* Use database row-level security rules.
* Add file upload restrictions.
* Add consent for personal data and uploaded documents.
* Do not send uploaded client files to AI tools without an explicit consent process.
